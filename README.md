# Парсер Go 1.27 с AST

[Описание проекта](docs/AST.html) · [Деревья всех тестов](docs/trees/index.html)

Парсер использует Flex, Bison в режиме LALR(1) и C++17. В грамматике сохраняются `%expect 0`, пять уровней приоритетов бинарных операций и `%left` для `[` и `.`. [Спецификация Go](https://go.dev/ref/spec)

## Сборка и запуск

Выполните команды из папки проекта. Flex, Bison и g++ должны быть в PATH.

```powershell
powershell -ExecutionPolicy Bypass -File ./build.ps1 -Test
./build/parser.exe ./tests/valid/if_else.go --html ./build/if_else.html
./build/parser.exe ./tests/valid/if_else.go --dot ./build/if_else.dot
powershell -ExecutionPolicy Bypass -File ./tests/Test-Parser.ps1 -ExportTrees
```

HTML открывается в браузере в режиме графа с узлами и рёбрами. Полотно можно перетаскивать и менять масштаб. Щелчок по узлу показывает его ID, координаты и соответствующий фрагмент исходника. Есть режим раскрываемого списка. DOT можно отрендерить отдельно с помощью Graphviz.

`-ExportTrees` запускает все тесты и обновляет каталог `docs/trees/index.html`. Для отклонённого файла HTML показывает диагностику. Если грамматика успела построить дерево, граф доступен и для ошибки AST.

`--check` выполняет те же проверки и убирает сообщение `AST OK`. `--trace` включает трассировку Bison. Если имя файла отсутствует или равно `-`, программа читает stdin. Код 0 означает успех, 1 — ошибку исходника, 2 — ошибку запуска или работы с файлом.

## Как получается исполняемый парсер

1. Bison читает `parser/parser.y` и генерирует `build/generated/parser.tab.cpp` с `yyparse()` и `parser.tab.hpp` с типами токенов и интерфейсом.
2. Flex читает `lexer/lexer.l` и генерирует `build/generated/scanner.cpp` с `yylex()`.
3. g++ компилирует сгенерированные файлы вместе с `main.cpp`, `Parser.cpp`, `LexerSupport.cpp` и реализацией AST.

Редактировать нужно `parser.y`, `lexer.l` и написанные вручную файлы. Содержимое `build/generated` восстанавливается при сборке.

## Зачем нужен main.cpp

`ReadArguments()` читает аргументы и переводит пути Windows из UTF-16 в UTF-8. `Run()` разбирает параметры, читает файл и вызывает `ParseSource()`. При запросе экспорта он открывает отдельный выходной файл и вызывает `AstWriter::Html()` или `AstWriter::Dot()`. `main()` настраивает консоль и возвращает код завершения.

## Зачем нужен Parser.cpp

`ParseSource(source, filename)` используется консольной программой и C++-тестами. Функция сбрасывает AST и состояние лексера, проверяет длину и UTF-8, пропускает начальный BOM и готовит буфер Flex. Затем она вызывает `yyparse()` и `Ast::Finish()`. Деструктор `ScannerGuard` освобождает буфер и внутренние ресурсы Flex.

После успеха `astRoot` указывает на узел `File`. При ошибке корень равен `nullptr`. Память дерева принадлежит парсеру и очищается при следующем вызове `ParseSource()`. Разбор выполняется последовательно, поскольку Flex и Bison используют общее состояние.

Bison может сгенерировать таблицы без `main.cpp` и `Parser.cpp`. Эти файлы нужны для запуска сгенерированного кода в консольной программе и в тестах.

## Где устроено дерево

| Файл | Роль |
|---|---|
| `parser/parser.y` | Токены, правила, приоритеты и короткие вызовы конструкторов узлов |
| `parser/ast/Ast.h` | Виды узлов `AstKind` и их данные |
| `parser/ast/AstBuilder.cpp` | Создание узлов и списков, присвоение ID, публикация корня |
| `parser/ast/AstTypes.cpp` | Разбор общей формы квадратных скобок, составных литералов и групп параметров |
| `parser/ast/AstChecks.cpp` | Проверка `:=`, `range`, `select`, type switch и переходов |
| `parser/ast/AstWriter.cpp` | Формирование HTML и DOT |

У каждого узла есть вид, координаты, дети и при необходимости текст. Например, `1 + 2 * 3` образует `Binary("+")` с числом слева и `Binary("*")` справа. В `user.age := 20` селектор слева от `:=` приводит к диагностике AST. В `user.age = 20` тот же селектор сохраняется как цель `Assignment`.

## Что означают значения токенов

`%token <stringValue> HEX_LITERAL` связывает токен с полем `%union`. Лексер передаёт запись числа, например `0xFF`. AST хранит вид `HexLiteral` и свою копию текста. Так сохраняются основание, разделители, степень и цифры больших констант. `RUNE_LITERAL` использует `integerValue`; узел хранит исходную запись и декодированный код руны.

Анализ имён, типов и вычисление констант идут после AST. Например, `a[T]` может означать индекс или инстанцирование, поэтому узел `IndexOrInstantiation` сохраняет оба возможных смысла. Точно так же `T(x)` строится как вызов с именем `T`, пока не известно, является ли `T` типом.
