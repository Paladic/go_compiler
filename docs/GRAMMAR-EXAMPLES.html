Как читать примеры

Заголовок раздела — имя нетерминала из parser/parser.y. Каждая карточка — отдельная альтернатива после : или |. Зелёный блок показывает её запись в грамматике, серый — участок исходника, который она распознала.

Нажмите «Полный пример Go», чтобы увидеть весь вход, включая package и нужный контекст. Поиск слева учитывает имена правил, альтернативы, примеры и объяснения. Например, можно искать identifier %prec NAME_END, import_spec или «цикл».

Это примеры разбора синтаксиса. Парсер не выполняет программу, не вычисляет сложение и не создаёт переменные. Имена вроде a, T и pkg могут быть необъявлены: проверки имён и типов здесь нет. Принятие текста парсером ещё не доказывает корректность Go-кода.

Разберём identifier %prec NAME_END

package p
var age int
  1. Лексер выдаёт для int токен IDENTIFIER: имя встроенного типа не является отдельным ключевым словом.
  2. Правило identifier: IDENTIFIER {} распознаёт это имя.
  3. Альтернатива type_name: identifier %prec NAME_END распознаёт int как имя типа: родительская конструкция здесь ожидает тип.
  4. Правило type: type_name использует этот тип в variable_spec.
  5. Отдельная альтернатива identifier_list: identifier %prec NAME_END распознаёт имя переменной age. Роль имени определяется контекстом.

%prec NAME_END не соответствует символам исходника. Оно задаёт приоритет альтернативы для разрешения выбора между сдвигом и свёрткой (shift/reduce). Слово NAME_END в Go-файле не пишется. То же относится к ARRAY_CALL, EMPTY_SIGNATURE и CHAN_BARE.
